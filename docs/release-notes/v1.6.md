# pg_hardstorage v1.6

> Distilled for operators; the full commit-level detail is in the
> [`CHANGELOG`](../changelog.md).

This is a **minor** release. Nothing on disk or on the wire changes; the
24-month schema promise is untouched. It also contains everything in
v1.5.1.

## Very large databases stay within bounded memory

Backup, restore, `repo gc` and the read-only commands no longer hold
per-chunk or per-file state in RAM. Manifests stream from a disk spool,
membership sets spill to disk behind a Bloom filter, and `repo gc` takes one
fence checkpoint per sweep window. A killed restore resumes from an
append-only log (`.pg_hardstorage_restore_done.log`) by rerunning the same
command. `backup compare`, `audit`, `wal list`/`wal audit`, per-kind record
lists and the logical sinks are bounded too, and the PostgreSQL
`backup_manifest` ceiling is 1 GiB (was 256 MiB).

Measured: 24M-chunk repositories ran every read-only command under
`GOMEMLIMIT=512MiB`; `backup compare` of two 2M-file manifests dropped from
657 MiB to 170 MiB. See [Very large databases](../how-to/operating/very-large-databases.md)
for sizing guidance.

New: `backup --chunk-size`, `backup.chunk_size` / `backup.timeout`,
`restore --tablespace-mapping-all` (#79), the `backup:` block (#75).

## `repo gc` leaves a clean repository

The filesystem backend prunes the empty `chunks/` and `manifests/`
directories gc used to leave behind, and leftovers of a killed gc are
reaped. Randomised model, fault-injection and writer-race tests found no way
to make gc delete a referenced chunk.

## Leaks and security

- A backup cancelled during the lease settle window no longer blocks every
  later backup for 15 minutes; the scheduler no longer relaunches a wedged
  task on every tick; zstd memory no longer grows with core count.
- A manifest copied over another backup's key is refused (rollback/replay).
- Credentials in repo URLs are scrubbed from errors and events.
- The restore boot test and partial-restore sandbox no longer archive into
  the production repo.
- Key files for `kms rotate` and the approver key must be owner-only.

## Upgrade notes

- The scheduler skips a task whose abandoned run is still alive instead of
  relaunching it.
- `spill.DefaultMemEntries` dropped to 1M; spill-heavy commands trade a
  little speed for about 3x less memory.

## Known limits

- WAL segment manifests are unsigned; signing the chain needs a format
  change (planned for v1.7).
- `audit export-bundle` and the header-embedded PG `backup_manifest` still
  scale with size; sftp/scp keep empty directories after gc.
- A PITR-restored cluster keeps `archive_mode` as configured; decide
  whether it may archive into the production repo.

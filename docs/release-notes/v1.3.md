# pg_hardstorage v1.3

> Released 2026-08-26. Distilled for operators; the full commit-level
> detail is in the [`CHANGELOG`](../changelog.md).

This is a **minor** release because it adds surface — `recovery drill
--tablespace-mapping`, a per-deployment `drill:` block, `kms verify
--require-encrypted`, and day/week units on the retention duration
flags. Its centre of gravity, though, is **tests that were not being
run**.

`test/scenarios/` holds 174 scenario files. The make target ran **12**.
The other 162 were reachable only by invoking the testkit by hand, so
nothing executed them routinely — and unrun tests do not stay correct.
Running them is what surfaced most of what follows. `make
test-scenarios` now runs the whole corpus, and `make
test-scenarios-lint` schema-checks it in seconds without Docker.

## The two that mattered most

**`repo bundle import` rejected every chunk of every real bundle.** A
chunk key addresses the PLAINTEXT — the CAS hashes the body, then
compresses (zstd by default) before storing — while a bundle preserves
the on-disk layout and therefore carries the STORED bytes. Import
hashed what was in the tar and compared it to the key, which only
agrees when the chunk was written with the `none` codec. Since every
repository compresses by default, the air-gap bundle feature **did not
work at all**. It now decodes the envelope and verifies what the key
actually addresses; a chunk whose plaintext does not hash to its key is
still refused, so the anti-forgery guarantee is unchanged.

**`recovery drill` could overwrite live tablespaces.** The drill
restores into a temporary directory it creates and removes, so it reads
as a safe rehearsal. That is true of the main data directory. It is not
true of a non-default tablespace, which is restored to the absolute
path recorded in the manifest — on the host the backup came from, the
live tablespace. A command whose purpose is proving a backup is sound
could destroy production data, and `schedule --task drill` runs it
unattended. It now refuses such a backup unless a mapping covers it,
before any bytes are written.

## Reported by operators

Both from [@marsqd](https://github.com/marsqd), against 1.2.4:

- **Alibaba Cloud OSS repositories could not be created** (#52). The S3
  addressing style was resolved as `path_style || endpoint != ""`, so a
  custom endpoint forced path-style and `path_style=false` could not
  turn it off — virtual-hosted addressing, which OSS requires, was
  unreachable.
- **`--keep-for 30d` was rejected** (#52) with `unknown unit "d"`. The
  report named one flag; there were three. `wal prune --keep-since` had
  even had its help amended to tell operators to convert by hand ("e.g.
  14d → 336h"), absorbing the defect as documentation.
- **`recovery drill` had no `--tablespace-mapping`** (#53), and the
  scheduled drill had no way to receive one.

## Also fixed

- **GCS answered "object missing" only at open, never mid-stream**, so
  every caller keyed on `ErrNotFound` stopped recognising a plain
  missing object — including the backup lease's
  released-between-put-and-read retry, turning a routine concurrent
  release into a failed backup.
- **A backup could adopt a chunk it cannot decrypt** in a repository
  holding more than one KEK. The cross-DEK guard probed once per CAS,
  which is sound for a single-KEK repository and false for a mixed one —
  exactly the configuration it defends. The backup exited 0 and failed
  at restore.
- **`logs --since 24h` was rejected by journalctl** though the flag's
  own help offers `"24h"` as its first example, and `notfound.unit`
  detection keyed on an exit code journalctl never returns.
- The security and correctness audit inherited from the 1.2 line: an
  unauthenticated non-loopback control plane, job-supplied repo URLs an
  agent would stream a live cluster into, LSN-0 refusals, three leaks,
  and a lease renewal that panicked on a backward clock step.

## Upgrade notes

Three behaviours change. Nothing on disk or on the wire changes — the
24-month schema promise is untouched — but an upgrade can surface these:

1. **A non-loopback control plane now refuses to start** without
   `auth.token_file` or `tls.client_ca_file`. Loopback is unchanged.
   Server-TLS-only deployments must add one of the two.
2. **`logs` on a unit systemd does not know now exits 6**, not 0.
   Anything scripted against the old success will see the change.
3. **A drill of a backup with non-default tablespaces now fails**
   without a mapping, where it previously proceeded and overwrote the
   recorded locations. Set `drill.tablespace_mapping` for those
   deployments. **A drill that appeared to pass before may now fail —
   that is the bug surfacing, not a regression.**

## Performance

WAL pruning reads manifests only for the prunable prefix instead of
every segment. The chunker's hot path no longer copies the live tail
after each chunk: a 4 MiB stream allocates ≤4 objects instead of 285,
with bit-identical boundaries. The adopted-chunk commit gate fans out,
the DEK-reuse manifest read is bounded, and `/readyz` caches its probe.
